## Findings

**F1 · HIGH · FIX + REGRESSION TEST: the provider is still swapped silently at startup and on reload**
- **Where:** `internal/config/load.go:858-861` and `:903-906` (`large = defaultLarge` from another provider), `:159-177` (now only `slog.Warn`), and the reload path in `internal/config/store.go:1496`.
- **Claim in docs:** README.md:79-82 and docs/agent-cli-local-setup.md:856-862 call this a "known limitation". They say it is reduced by setting `AGENT_CLI_ALLOWED_MODELS`. DECISIONS says it cannot fail closed, otherwise `agent-cli login` would not work.
- **Wrong assumption:** login only needs the config to load. It never needs an LLM call on a substitute provider. Load can keep succeeding while `buildAgentModels` (`coordinator.go:1043`) refuses when the provider it resolved differs from the one configured.
- **Failure scenario:**
  - The selected catalog model loses its key (for example `$(pass show …)` fails under cron) or its model ID disappears.
  - The process then runs on the first catalog provider that still has credentials, and the only signal is a log line.
  - With the allowlist from docs:533 (`zai:glm-5.3 … main:qwen3.8 …`), the allowlist does not block it whenever the fallback provider's default model is on the list. So the documented mitigation overclaims.
  - A routine is the worst case: `routineReport` (`internal/cmd/routine.go:497-525`) has no provider/model field, the ledger is opt-in, and `scheduleEnv` does not pass it on. A scheduled run leaves no evidence of which provider it used.
- **Evidence:** `TestStartupFallbackIsNotPersisted` (`internal/config/model_pin_test.go`) asserts `NotEqual("openai", …Provider)`, meaning the in-memory switch to anthropic is the expected behaviour. The test passes on the candidate.
- **Fix:** if `LargeFallback`/`SmallFallback` would cross providers, fail at the first LLM call with "selected model X unavailable". Allow same-provider fallback only.
- **Regression test needed:** openai configured without a key, anthropic with a key → `run` exits non-zero and the fake server sees 0 anthropic requests.
